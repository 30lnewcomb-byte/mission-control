# Mission Control 🚀

Mission Control is a Windows 11 space-launch companion planned around two interfaces:

- A floating desktop dashboard for live countdowns, weather, mission details, and launch coverage.
- A companion card in the actual Windows Widgets board.
- One shared local core so both interfaces agree about launch status.
- **Ori Small MC**, a local AI chat assistant powered by Qwen3.5 4B through Ollama. It can discuss general topics as well as space launches.

## Current status

**Foundation stage — not yet an installable app release.** The repository contains the deterministic countdown core, Windows CI, the Ori Small MC Ollama client/setup, and a Launch Library 2 upcoming-launch reader with response caching and a US launch-site filter. Regression tests cover the countdown rules, Ori Small MC chat requests/errors, and LL2 schedule parsing, caching, US filtering, malformed responses, and launch-status trust boundaries. The Windows CI workflow also builds the WPF desktop dashboard. An initial WPF desktop dashboard and local general-chat UI are present, including request-scoped context for the selected launch. The actual Windows Widgets provider, authoritative NASA/SpaceX status and coverage adapters, weather integration, shared local service, and final one-command installer are still unfinished.

## Ori Small MC

- Model: `qwen3.5:4b`
- Ollama model name: `ori-small-mc`
- Local endpoint: `http://localhost:11434/api/chat`
- Persistent instructions: `models/OriSmallMC.Modelfile`
- Setup script: `scripts/Install-OriSmallMC.ps1`
- .NET API client: `src/MissionControl.Core/OriSmallMcClient.cs`

The setup script installs Ollama through Windows Package Manager when available, pulls the base model, and creates `ori-small-mc`. It can also be run after installing Ollama manually. The final Mission Control installer should call this setup as an optional component and explain the several-gigabyte download before starting it.

Ori Small MC supports general conversation, learning, writing, brainstorming, coding, and other ordinary topics. Its Mission Control instructions remind it not to invent live data. Launch countdown math and authoritative launch states remain controlled by deterministic code.

## Project principles

1. **Status must be evidence-based.** Passing the scheduled time does not prove liftoff.
2. **T−/T+ must be deterministic.** Countdown math is ordinary code, not generated by AI.
3. **Be honest about uncertainty.** A delay, scrub, or unknown status must never be presented as confirmed liftoff.
4. **Local-first.** Cache data, keep preferences locally, and make the local AI optional.
5. **One backend, two interfaces.** The dashboard and Windows widget share the same state.
6. **Safe installation.** The eventual one-paste installer must verify downloads and provide clear errors and uninstall/update paths.
7. **Graceful AI fallback.** Mission Control must remain useful if Ollama is not installed or running.

## Launch schedule and status trust

`src/MissionControl.Core/LaunchLibrary2Client.cs` reads the LL2 v2.3.0 upcoming-launch endpoint. It caches successful responses in memory for ten minutes by default and can filter to launch sites whose country code is explicitly `US`; unknown locations are not guessed. LL2 data is schedule metadata only. The adapter never sets an actual liftoff timestamp and does not promote an LL2 “Launch in Flight” label into the canonical in-flight state. A separate trusted status adapter is still required before Mission Control may show T+.

Planned next data sources are official NASA/SpaceX status and coverage links plus a weather provider for launch-site and home weather. A scheduled time from a calendar API alone is not sufficient evidence to switch to T+.

## Windows desktop preview

The first desktop dashboard is a native WPF application for Windows 10/11. On a Windows development machine with the .NET 8 SDK, create a self-contained Windows x64 preview ZIP by running:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\Publish-MissionControl.ps1
```

The output is `artifacts\MissionControl-win-x64.zip`. It contains the self-contained dashboard plus the optional local Ori Small MC setup script and model instructions; it does **not** include the multi-gigabyte Qwen model. The publish script only clears its own `artifacts\MissionControl` output directory and its generated ZIP before rebuilding.

The GitHub Actions workflow also builds that ZIP on pushes to `main` and uploads it as the `MissionControl-Windows-x64-preview` artifact for 14 days. Find the latest runs at [GitHub Actions](https://github.com/30lnewcomb-byte/mission-control/actions). This is a preview package, not the promised one-command installer: it does not yet register a Windows widget, install an updater, or set up trusted liftoff status/weather/live coverage feeds.

## Development

The .NET core is under `src/MissionControl.Core`. Run the test suite with `dotnet test tests/MissionControl.Core.Tests/MissionControl.Core.Tests.csproj --configuration Release`. See `docs/architecture.md` for current boundaries and next steps, and `scripts/Install-OriSmallMC.ps1` for local model setup. This is not yet a complete Windows desktop application.
